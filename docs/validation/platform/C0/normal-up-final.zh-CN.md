## 2026-09-28 复测：x64 工作后的回退与修正

同一方法（`clock_boot_bench.mjs`，5 组 AB/BA，比较对象仍为 C0 前的 `bb8979f3`）对 2026-09-28 的 release 产物复测，**初测未通过**：启动中位数 3504.4 → 4022.6 ms，比例 **1.148**；样本很集中（基线 3462–3524 ms、当前 3970–4051 ms，指令数相同），不是噪声。与 09-27 冻结产物直接比较为 3811.3 → 4025.2 ms（+5.6%），即 C0 自身约 +8.8%，之后的 x64/X5 工作又加了约 5.6%。

用 V8 `--cpu-prof`（200 µs 采样）比较三个构建各一次启动的自身时间，增加集中在 32 位解释器的取指与内存路径：

- 长模式分支内联在 32 位热函数里：`get_phys_eip` 因加入 IA-32e 取指翻译不再被内联（自身时间从 0 变为 126 ms），`read_imm8`、`safe_read*`/`safe_write*`、`translate_address*` 同样各带一段 IA-32e 代码。
- X5 为“重映射后的低地址空洞是 open bus”把 `read_imm8` 的读取从直接读 `mem8` 改成经 `memory::read8`，每次取立即数都要做映射范围判断；`read8`/`read32s` 因调用方变化不再被内联（`#[no_mangle]` 导出函数上的 `#[inline]` 无效）。
- 每条解释指令：C2 的每核统计以核号索引两次 64 位累加；C3 的“进入 64 位模式则退出解释块”每条调用 `x64::state::mode()`（5 次读取）。

修正（语义不变）：

1. IA-32e 分支全部移到 `#[cold] #[inline(never)]` 函数（`ia32e_phys_eip`、`ia32e_fetch8`、`ia32e_translate`、`ia32e_read/write[128]`、`wide_read_write`），32 位路径只剩一次标志判断。
2. `read8`/`read16`/`read32s` 拆成总是内联的 RAM 路径与不内联的映射范围路径，导出符号改由同名 `export_name` 包装提供。
3. 取指缓存（`last_virt_eip`/`eip_phys`）只缓存普通 RAM 页：映射范围（VGA、MMIO、低地址空洞）的页每次经总线读取，缓存命中时即可直接读 `mem8`（恢复 C0 前的快路径），open bus 语义不变（`legacy_low_hole.mjs` 三后端通过）。
4. 每条指令的退休数/REP 元素数先累加到两个普通计数器，在核切换、复位以及每次读取统计（`core_statistics_get/addr`，含快照）前并入按核统计；`core_statistics.mjs` 的逐核精确计数仍通过。
5. 解释块的 64 位模式检查改为读 `x64_cs_long`（CS.L 只在 EFER.LMA=1 时为 1，复位与 `reset_extension` 一起清零）。

逐步复测（均为 5 组、同一基线）：1.148 → 1.107（第 1、2 项）→ 1.100（第 3 项）→ **1.095**（第 4、5 项），固定工作量比例由 1.129 变为 0.94–1.09（该项噪声较大）。
